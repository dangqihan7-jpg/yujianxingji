# 语音输入体验优化（2026-10-24—25）

本次在已有首页语音输入上优化状态反馈，不改变 `/api/stt` 的PCM协议、60秒上限、讯飞鉴权或小时限流。

## 交互

- 录音时显示实际录音计时和60秒上限；停止采集后结束计时，不将识别等待画成进度。
- 等待权限、录音、上传识别均提供明确取消入口。取消释放麦克风、终止请求，迟到结果不写入输入框。
- 识别中说明录音已结束，正上传并转文字；取消后仍可继续打字。
- 失败后“重新录音”开始新的一次采集，不偷偷重传旧录音。未配置、额度用尽与普通网络失败分别提示，不影响手动输入。
- 成功与失败提示保留，不因普通控件刷新立刻消失。结果仍追加到最新输入、可编辑，不自动提交规划；超过输入框容量时保留原文和完整识别文本。
- 手机端操作按钮保持至少44px触摸目标，状态文字可换行；减少动态效果时禁用装饰动画。
- 首页模型状态从“AI 已连接”改成“AI 服务已配置”，配置存在不代表当前网络、授权或回答质量已验证。

## 初始化修复

真实浏览器检查发现，原先首页首绘早于共享变量 `briefBusy` 初始化，支持麦克风的安全上下文会触发 ReferenceError，导致语音按钮未绑定。现将初始渲染移到所有模块初始化后、`init()` 前，保留忙碌状态守卫，并加入完整组装脚本回归。

## 验证边界

本轮使用模拟麦克风、Web Audio与上游验证状态切换、取消和追加，不采集真人声音、不调用真实讯飞服务。真实录音准确率与应用开通仍须按 [语音输入验收](stt-verification.md) 由站长配置后验证。此前文档中的2026-10-23部署记录是历史记录，本轮不会把它冒充新的真人识别结论。

2026-10-25 构建、产物校验与完整 `npm test` 30套件通过，其中 STT 后端13组、前端31组（含完整页面初始化回归）。本地桌面和375/390/414px iframe外宽检查通过；滚动条占15px，实际内容宽分别360/375/399px，无横向溢出，录音与取消按钮高度46px。模拟语音文字追加与识别取消保留原文均通过。这是浏览器布局与模拟流程验证，不等同于真人或iOS设备验收。维护证据在仓库外保留，不提交账号数据、私密配置、录音或临时产物。`competition-evidence/` 的既有JSON在独立副本测试前后比对，保持原样。
