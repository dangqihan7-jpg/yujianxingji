## 人工补图与旧照片更新

先运行 `npm run photos:check`，或固定审计口径 `node scripts/check-photos.mjs --year 2026 --max-age 2`。当前无图 53 处、有图 42 处；完整 id / 名称 / 城市清单和输出样例见 [照片审计](photo-audit.md)。无图和加载失败使用明确标识的图形占位，不借其他景区图片或生成图填空。

新增照片只接受未经编辑改色的真实照片：自己实拍，或能确认实际地点、作者和明确使用授权的原作。拒绝 AI 生成、合成、滤镜改色或改变画面内容的照片；仅搜索结果、转载页、摄影平台标签不构成授权。保留原始照片和许可证据，别把上传/网页编辑日期写成拍摄日期。高德照片需要按具体图片核对来源和使用条件，不能统一标为已人工审核。现有照片的历史缩放、压缩和卡片裁切说明继续保留，不宣称它们全无后期处理。

1. 将核对后的 JPG 放在**仓库根目录**，例如 `hn-wansui.jpg`；构建会将它嵌入 `/assets/hn-wansui.jpg`，无需改前端代码或服务端资产清单。当前组装器支持的是根目录 JPG；不要仅上传到一个新建的 `assets/` 目录。
2. 在对应地点增加 `image: "/assets/hn-wansui.jpg"`，即可在重新构建后显示。用于正式发布的照片同时记录下列可选元信息；未知年份省略或设为 `""`，不要猜测。

   ```json
   {
     "image": "/assets/hn-wansui.jpg",
     "photoSource": "实拍",
     "photoYear": "",
     "photoAuthor": "填写摄影者",
     "credit": "填写摄影者与真实授权说明"
   }
   ```

   `photoSource` 是出处标签，例如 `实拍`、`wikimedia`、`高德`，不代表许可结论。公开授权照片还应写 `photoReference` 原始文件页、`licenseUrl`、`photoLicense` 与 `photoCaption`；自有实拍保留摄影者授权记录。已知拍摄年份可写整数 `2026`，已知原始日期写 `photoTakenAt: "2026-10-15"`，日期有多精确就保留多精确。示例年份为空仅演示未知情形，并非该景区已有照片。
3. 如替换已有文件，计算 SHA-256，将 `image` 的 `?v=` 更新为哈希前 12 位，同时更新引用同图的路线封面。新文件使用新名称时不依赖版本参数也可加载；不要删除旧来源或将更新年份冒充拍摄年份。按需补充 [照片记录](photo-catalog.json) 以及 README 的作者、许可和原图链接。
4. 运行 `npm run photos:check`，人工复核“无图 / 无出处 / 疑似老照片”；脚本另外提示年份未知和异常，不自动修复。完成 `npm run build`、`npm run validate`、全量 `npm test`，测试不过不提交。检查电脑/手机的正常图片、缺图与加载失败占位、详情原图、来源链接及页面溢出。
5. 只提交源码、照片和公开元数据；密钥保留服务端环境变量，不进仓库或前端。同步发布前备份现有代码与数据库，保留私密配置、账号数据和 `.local` 数据目录链接。

脚本可用 `--year` 固定审计年份、`--max-age` 配置疑似老照片阈值、`--file` 使用其他数据文件、`--json` 输出结构化清单。默认“超过两年”按年份差判断，2026 年只标记 2023 年及以前的照片；这不是过期判定，也不能证明照片内容仍与景区现状完全相同。更多参数见 `node scripts/check-photos.mjs --help`。

## 后续更新规则

优先选择近两年、能核实具体地点的真实照片；同时核对清晰度、构图和明确的使用许可。拍摄时间与上传、网页编辑时间分开记录，不将旧照片称为实时画面。找不到合适新图时保留可确认的旧图并报告日期；高德搜索图片另有来源，不能声称全部经过人工核对。

1. 在仓库根目录替换对应 JPG，更新 `henan.json` 中 `photoReference`、`licenseUrl`、`credit`、`photoCaption` 和 `photoTakenAt`。
2. 图片 URL 的 `v` 参数使用文件 SHA-256 前 12 位，替换后同时更新引用该照片的路线 URL，避免浏览器继续读取旧缓存。根目录文件名保持稳定，旧 URL 仍可访问。
3. 更新 README 的照片来源列表；CC BY-SA 图片继续按相同许可提供。未经授权的图片、生成的仿真景点图不加入实景库。
4. 执行构建、校验、离线生成与测试，检查手机/电脑首屏、详情来源链接、图片加载和页面溢出，再同步 GitHub 并备份部署。

Codex 定期维护任务负责检查与择图；网站服务本身未实现自动抓图。只有通过核对的新照片才会发布，具体运行时间以 Codex 中的维护任务设置为准。
