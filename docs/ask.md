# 当前行程 AI 问答

规划页与行程总览页右下角的问答入口用于解释当前草稿，不重新生成或修改行程。打开底部抽屉后输入问题，服务器将经过校验的行程快照和本次问题交给星火 X2.5，返回简短回答；这一接口不经过五智能体流水线，也不调用海报、分享或识图接口。

问答历史只保留在本页内存中，刷新或关闭页面后消失，不写入 localStorage、账号草稿、分享快照或本站数据库。每次提问使用提交时的当前行程；抽屉里的旧回答仍是当时的上下文，不会因为编辑行程自动更新。界面始终标注“AI 回答仅供参考，出行前请核实”。

## 服务配置与官方依据

本接口复用服务端已有的 `LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL`，不增加新的密钥，不使用 `XF_VISION_*` 或 `XF_TTI_*`。MaaS 基础地址为 `https://maas-api.cn-huabei-1.xf-yun.com/v2`，模型需为控制台已授权的 `spark-x2.5`、`spark-x2.5-4b` 或 `spark-x2.5-1.7b`。

2026-10-18 核对[讯飞官方 X2.5 HTTP 文档](https://www.xfyun.cn/doc/spark/Spark-X2.5.html)：问答请求采用 `/chat/completions` 与 Bearer 鉴权，使用 `max_completion_tokens` 限制回复，关闭深度思考，不显式设置固定采样参数。实现的回复额度为1000 token、最长等待25秒；只读取最终 `message.content`，不展示推理内容。问答使用独立轻量调用适配，现有规划接口的参数与行为保持不变。

本地使用已存在的环境变量或 `node --env-file=.env scripts/dev.mjs`；阿里云只维护权限600的 `/etc/yujianxingji.env`，修改配置后重启 `yujianxingji.service`。不要在源码、浏览器、聊天、测试夹具或日志里放真实密钥。配额复用已有 `model_usage`，无需新增数据库迁移。

## 请求与返回

`POST /api/ask`，`Content-Type: application/json`，请求体包含 `question` 和当前 `trip`。`trip` 包含地点清单、天数及完整分日站点；客户端只构造必要的旅行上下文，不直接发送整个账号草稿。服务器再按白名单取字段，不附带账号资料、坐标、照片、原始需求或私密备注等元数据。用户输入的问题与必要的地点文字会发送至讯飞；本接口不提供文字内敏感信息的自动脱敏服务。

示例：

```json
{
  "question": "第一天有几个景点？",
  "trip": {
    "places": ["龙门石窟", "洛阳博物馆"],
    "days": 2,
    "schedule": [
      {"day": 1, "stops": [{"name": "龙门石窟", "city": "洛阳", "duration": 120, "travelMinutes": null}]},
      {"day": 2, "stops": [{"name": "洛阳博物馆", "city": "洛阳", "duration": 90, "travelMinutes": null}]}
    ]
  }
}
```

成功返回 `{"answer":"……"}`。响应不包含用户信息、密钥、原始上游响应或模型推理。接口不保存问题、回答或行程副本，只持久化限流计数。

`question` 最多600字，行程为1—7天、1—15站，沿用分享快照的名称、日期、停留时间和交通分钟数校验。可选 `mode`、`start` 及站点 `category` 用于区分交通方式、出发时间和景点/餐饮/住宿；服务器也接受现有 `{days, stops:[{place, day, duration}]}` 格式并先转成同样的公开快照。目录地点按名称与城市重新匹配，附上目录的公开简介、参考链接与程序计算的每天站点数量，不相信客户端随意提供的简介或地点ID。当前不发送用户费用表，交通费用与实时票价保持未知。

## 诚实性与边界

系统提示将模型限定为“河南周末游行程助手”，目标为3—5句简短回答。只回答与当前行程有关的问题；行程 JSON 和用户文字都是数据，不能改变系统规则或授权模型执行操作。问题与行程无关时礼貌引导回行程话题；本站没有实时天气服务，不能把天气猜测当作查询结果。

营业时间、票价、预约、开放政策和未核算的交通费用均不得凭模型记忆编造。没有可信价格时应明确“不知道当前票价”，不能为了演示强行生成一个价格区间。服务器对问题或回答中识别出的票务、营业、预约、优惠等主张采用保守兜底，明确说明当前资料未知。相关回答必须以“请以官方信息为准”结束；正文先限长、后追加兜底句，不能在截断时丢掉该句。免责声明不能替代对事实的核实。

明确询问某日数量时，先进行一次直接模型调用，最终数量和名称用该日快照的程序事实核对生成，不能因模型另一句恰好出现正确数字而放行矛盾数量。景点数不含餐饮和住宿，未分类站点另行说明；询问超出当前天数的日期时明确没有该日安排。询问行程开始/出发时间时只使用用户设置的 `start`，并区分排程设置和景区营业时间。未知交通不能按零分钟或零费用计算。

修改草稿后应重新提问，旧回答不作为新行程事实。系统提示和关键词守护并非通用事实核验器：未覆盖的复杂措辞、行程建议和其他自由回答仍可能不准确，应以实际行程与官方资料复核。本次自动测试使用模拟上游，不代表真实模型质量、抗提示注入能力或全部语言表达已验收。

## 独立配额与失败提示

按 UTC 日，匿名访问者10次、登录用户30次、全站200次，scope 使用 `ask:`，与规划、海报、分享和识图额度相互独立。身份由现有服务端认证解析，匿名按可信来源地址生成哈希，配额表不保存原始 IP；不能通过前端自称登录绕过配额。通过校验并获准的模型尝试计数，上游失败也计数，不自动重试。明显不支持的天气等无关问题可直接礼貌拒绝，不调用模型、不扣模型次数；其余问题直接调用一次模型。

| 情况 | 返回与处理 |
| --- | --- |
| 空问题、无效或缺少行程 | 友好输入错误，不调用模型。 |
| 非同源请求或不支持的方法 | 拒绝请求，不消耗模型额度。 |
| 今日次数用完 | HTTP429及中文限流提示，不调用模型。 |
| 需要模型回答，但模型配置缺失或配额数据库不可用 | HTTP503及明确中文提示，不崩溃、不假装生成回答。 |
| 模型连接失败、超时、空回复或异常响应 | 友好失败提示，不透出上游响应与内部错误。 |
| 抽屉关闭或切换离开适用视图 | 取消本次请求，迟到回答不覆盖后续会话。 |

## 维护与验收

修改后先运行 `npm run build`、`npm run validate` 和完整 `npm test`，通过后才提交。接口测试使用 mock 模型和隔离 SQLite，覆盖正常回答、跨日矛盾数量、未分类/不存在日期、已知开始时间、中文票价/预约/隐含折扣兜底、官方尾句保留、空问题、无关问题、匿名/登录/全局限流、未配置、异常上游及隐私白名单。前端测试覆盖入口、提交、会话内历史、切换视图、取消、示例轮换与不修改草稿；手机375px及桌面需检查输入框、列表滚动和按钮可达性。

真实服务验收应使用两日行程核对首日地点数，再问未知门票/预约、无关天气问题和额度提示。真实调用会消耗模型额度，不把模拟回答或测试截图描述成真实模型能力；未实测时明确记录范围。发布前备份现有代码与 SQLite，保留账号、私密配置、数据目录链接，部署后再核对页面和服务状态。
