# 前端 UI 与维护

## 视觉方向

以真实河南风景呈现周末旅行的氛围。使用米白纸色、墨色文字和朱砂红主操作，宋体标题与无衬线正文形成层级。首页依次展示云台山实景首屏、需求输入、可切换的三条路线和六城探索入口；现有规划、导出、登录与保存流程继续通过原事件和 API 工作。

参考 MotionSites 的旅行主题页面展示方式：https://motionsites.ai/?prompt=aetheris-voyage-hero 。页面结构、中文内容和样式按本项目实现，图片使用已有素材及许可；无需接入 MotionSites 服务即可运行。

## 文件与构建

- `app.html`：页面骨架、顶部导航、弹窗和应用主逻辑。
- `showcase.js`：首页内容、首屏滚动入口、路线切换与行程总览。重绘首页保留尚未提交的需求文字。
- `ui.css`：本次视觉系统，排在 `styles.css`、`showcase.css`、`decision.css` 之后。共享色值、首页构图、手机布局和减少动态效果规则集中在此。
- `scripts/assemble.py`：将四份样式和功能代码组装到 `worker/index.js`。修改作者文件后执行 `npm run build`；本地 Node 服务也需要重启才能读取新构建。

继续沿用原生 HTML/CSS/JavaScript；没有新增运行时依赖、外部字体或视频资源。`worker/index.js` 是生成产物，必须与作者文件一同更新；离线页由 `node scripts/offline.mjs` 生成且不提交。

## 交互与检查

首屏“开始规划”滚动到需求区并聚焦输入框；“探索主题路线”滚动到路线区。用户可通过键盘访问按钮，焦点有可见描边。首屏的图片与文字使用一次性轻动效，路线照片在悬停时小幅缩放；`prefers-reduced-motion: reduce` 禁用动效及平滑滚动。

手机端保留登录与旅程入口，四个主视图位于第二行；规划页通过“好去处 / 地图 / 我的行程”锚点跳转，锚点留出固定导航高度。隐藏控件由 `[hidden]` 统一控制，避免响应式 display 规则重新显示未启用的按钮。

修改后运行 `npm run build`、`npm run validate` 和 `npm test`，并在浏览器检查：

1. 桌面与手机首屏的图片、文字、主入口和页面横向溢出。
2. 首屏跳转、需求文字、路线切换、载入路线、城市入口与照片来源。
3. 地图规划、行程总览、行程检查及登录弹窗。
4. 线上高德地图加载和账号保存；模型来源标识保持真实。

照片的作者与许可仍在 README 和站内资料说明中列出。测试不应把尚未核算的交通或预算视为已满足。

地图在隐藏时暂停自动尺寸监控，重新显示后在布局帧内恢复；发现零尺寸画布时重建地图实例，草稿和交通缓存仍由应用状态管理。旧实例的完成事件不能把新实例误标为已加载。对应回归在 scripts/test-map-loader.mjs。


## 新用户引导与手机操作

首页增加三步说明、路线天数与站数，以及复用现有规则规划的示例入口。查看示例不会改动草稿；只有明确载入才会替换，支持撤销。模型提示区分游客与登录场景。手机规划分区导航固定在主导航下，锚点预留两层导航高度，示例按钮和分区入口保留可触摸尺寸。


## 路线预览与照片说明

三条路线有独立预览选择器，切换只更新路线区域，不重绘首屏或需求输入，不更改当前行程；按键后保留焦点和滚动位置。载入前可展开分日地点清单。路线主照片、行程每日封面和详情相册明确标注照片对应的城市与地点，详情相册使用完整画面，来源链接可直接打开。精选地点详情优先使用当前目录，避免旧草稿携带过时图文。行程总览增加导出入口，复用既有导出逻辑。

照片标注说明来源，不代表所有高德用户上传照片已经人工审核；此前用户报告的西安错图仍未取得具体截图，不能声称已完成该错图替换。

## 首页实景照片组

首页首屏展示云台山、龙门石窟、清明上河园、如意湖与红旗渠五张现有实景照片，复用目录中的图片和来源。缩略图可直接选择，桌面另有前后切换按钮；城市、地点和来源入口随选图同步更新。仅切换照片，不重绘需求输入或修改行程。默认每6秒淡入下一张，支持暂停；悬停、键盘焦点停留、弹窗打开、首屏离开视野、切换规划视图或浏览器后台时暂停轮播。启用减少动态效果时默认不自动播放，用户可主动开启播放。手机缩略图保留可触摸尺寸，标题与规划入口保持可见。
