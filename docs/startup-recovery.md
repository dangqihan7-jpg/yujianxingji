# 启动读取与草稿恢复

本次只修复前端启动恢复和失败反馈，不改后端接口、模型、地点数据或登录凭据。

## 行为

- `/api/config`、`/api/auth/me`、`/api/draft` 和恢复时的 `/api/validate` 每个请求最多等待 12 秒，包含响应正文读取时间；这不是整个启动过程的固定耗时。
- 网络失败、503、超时不作为游客身份。只有明确的 401 响应可进入访客模式。读取失败时暂停自动保存和行程编辑，避免把示例写回账号。
- 顶部提示当前读取状态；失败时可以“重试读取行程”。重复点击共用同一次恢复，重试不重新载入默认示例，超时后的迟到响应不能覆盖新结果。
- 账号行程验证完成后，不再等待补充地点搜索返回才解锁。
- 登录前仅暂存明确编辑过的行程；启动未完成、未编辑的默认示例不暂存。暂存草稿成功验证并应用后才移除。
- 若账号行程已经读取，但登录前暂存草稿损坏、验证失败或浏览器拒绝读取存储，可以重试，或明确点击“保留当前行程继续”。继续操作不删除原暂存，也不立即写入账号；之后主动编辑仍按原有流程保存。
- 问答遇到恢复失败时，提示关闭抽屉并使用顶部重试，不再无限显示“正在恢复”。

## 验证方法

先运行 `npm run build`，再运行 `npm run validate` 与 `npm test`。新增 `scripts/test-startup-recovery.mjs` 使用模拟请求、可控计时器和编译后的页面测试，不调用真实模型。

浏览器验收使用独立本地预览：模拟账号读取 503、请求悬挂、恢复成功，检查顶部反馈、重试状态、问答可用性和 375 / 390 / 414 / 1280 像素布局。异常模拟仅用于本地测试，不改生产账号或草稿。

## 本次实测结果（2026-11-02）

- `npm run build`、`npm run validate`、全量 `npm test` 33 个脚本通过。为保护比赛证据 JSON，完整测试在源码一致的独立工作区运行；原仓库证据文件哈希未变。
- 浏览器模拟配置请求 503：顶部重试可见、行程编辑保持锁定；悬挂请求 12 秒后显示超时，恢复正常响应并重试后解锁。
- 模拟已登录账号和两站草稿，实际本地 `/api/validate` 校验后，页面恢复为 2 站、10:00 出发，显示“已恢复上次保存的行程”。无效测试草稿曾触发保护性失败，修正测试素材后重试成功；未更改产品验证规则。
- 375 / 390 / 414 像素下无横向溢出，重试按钮高 44px；1280 像素桌面行程页正常。
- 恢复后打开问答，输入问题后发送按钮可用，关闭正常。本次只验证输入状态，不发送模型请求。
- Storage SecurityError、损坏暂存、显式继续不写云端、迟到响应及并发恢复由新增自动化用例覆盖，未在生产账号注入故障。
- 浏览器故障响应仅在本地验收期间模拟，结束后已移除。部署和线上结果另记于工作区部署记录。
