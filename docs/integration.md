## 高德配置步骤

1. 在高德开发者控制台创建应用，分别申请所需的 Web 端 JS API 和 Web 服务凭证，配置使用来源与配额。
2. 在服务端配置 `AMAP_SECURITY_CODE`、`AMAP_WEB_SERVICE_KEY`。前端只获取 `AMAP_JS_KEY` 与安全代理地址。
3. 按接入时的官方文档确认 SDK 版本、安全代理协议、许可与署名要求；将确认结果补入 README。
4. 实现地图加载与地点查询，再验证地点坐标和路线联动。模型生成的地点名称不能直接当作已验证的地图地点。

## 模型配置步骤

1. 确认赛事要求与实际服务商。如果选择讯飞服务，先确认具体产品、协议及授权模型；不要假定所有服务都兼容同一种 HTTP API。
2. 当前模板约定 `MODEL_BASE_URL`、`MODEL_API_KEY`、`MODEL_NAME`；若实际协议需要 App ID、API Secret 等字段，再扩展模板和配置校验。
3. 只由服务端访问模型；增加请求超时、调用频率与额度控制，日志不记录凭证。
4. 校验输出结构与地点真实性，并将行程标记为建议草案；失败时提供重试提示，不用虚构结果兜底。

## 完成接入后的验收

- 浏览器源码、网络响应、日志及 Git 历史中无服务端密钥。
- 缺少配置、鉴权失败、超时、限流时，页面能明确提示失败。
- 地图可加载，景点标记与实际查询结果一致。
- 行程建议可按天展示，地点可核验，路线基于地图服务结果。
- README 的运行命令、环境变量和能力状态与最终实现一致。
