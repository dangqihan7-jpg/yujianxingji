# AI 主导的旅行智能体

用户在 2026-10-12 明确要求项目“基于智能体，并以 AI 为主导”。已将候选选点与常规重排接入服务端智能体；旧规则示例仍明确使用规则模式。

## 已实现的流程

1. `/api/intent` 用现有讯飞接口提取需求；程序保护明确数字和排除要求，用户确认条件。
2. `/api/agent` 的 `select` 操作把目的地、主题、必去/排除地点和目录索引提供给模型。前端不预先用规则挑好景点。模型查询详情，自主选择地点、日期、顺序和停留时长。
3. 模型通过 JSON 行动请求白名单工具，服务端执行后把观察结果交回模型。模型可在上限内调整安排。
4. 最终行程必须与最后一次工具检查的地点、顺序、日期、时长一致。前端呈现依据和检查结果；用户确认后才替换草稿。
5. `reorder` 操作保留已有地点、停留时长和固定日期，只调整顺序与日期。局部重排仍只应用到选定日期。

AI 决定候选与行动，确定性代码校验输入和结果；模型不可用时显示 `source=rules`、具体原因和实际调用次数。没有成功执行工具的单次模型文案不能显示为完成的智能体规划。

## 工具与事实边界

| 工具 | 输入 | 实际行为 |
|---|---|---|
| `search_places` | `query`、`limit` 或 `ids` | 查询条件允许的河南目录，返回介绍、建议停留、注意项和资料来源；暂停开放地点不参与新候选。|
| `lookup_map` | 已查询地点 ID，每次最多 3 个 | 请求高德 Web 服务，返回同城地点/入口候选；不自动认定入口正确，也不把用户照片视为审核结果。|
| `check_itinerary` | 模型拟定的 `stops` | 验证必去、排除、城市、完整性和固定日期；核对游览、休息、已知费用和交通。已由用户确认的高德定位或高德地点坐标才参与路线查询。|

地图工具仅使用服务端固定的高德接口。模型不能指定网络 URL、运行代码、读文件、保存草稿或订票。目录片区坐标不能用来假装已核算交通。同城公交可查询；跨城公交、跨游览日转场、园区内部交通、排队与预约仍待确认。未知交通、费用保持未知，不能将预算目标当作实际总价。已知冲突会显示在检查结果中，不保证候选一定可行。

高德本轮交通估计在候选中显示查询时间。它不写入地图的路线缓存；载入后可重新核算，修改顺序后不复用旧结果。单次执行内按模式、两端坐标和城市缓存相同线路，减少重复查询。

## 接口

`POST /api/agent` 接受现有草稿字段，增加 `operation: "select" | "reorder"`；`engine: "rules"` 明确使用规则候选。

```json
{
  "operation": "select",
  "city": "洛阳",
  "days": 2,
  "start": "09:00",
  "mode": "driving",
  "maxHours": 6,
  "restMinutes": 30,
  "stops": [],
  "decision": {
    "intent": {
      "city": "洛阳",
      "requiredIds": ["hn-luoyi"],
      "excludedIds": ["hn-longmen"],
      "interests": ["culture"],
      "budget": 500
    }
  }
}
```

响应包含 `source`、`draft`、兼容排序视图的 `stops`、权威程序检查 `audit`、实际交通查询 `transport`、模型说明 `summary/reasons/pending`、工具记录 `agent.steps` 和调用计数；降级时附 `fallback.reason`。模型文字属于推荐依据，资料与可行性以工具检查和当日官方信息为准。此接口不修改账号数据库中的草稿。

旧 `/api/plan` 保留兼容单次排序接口与离线规则示例；在线主入口和重排入口已切换到 `/api/agent`。离线版只执行本地规则，不调用模型或地图。

## 调用边界

每次执行硬上限：4 轮模型、8 次工具、8 次高德查询尝试、50 秒总等待。单轮模型等待仍最多 25 秒，高德最多 12 秒，都受整体取消信号限制。模型请求失败不自动重试；每次实际模型请求前单独调用现有身份与额度控制，失败尝试也计数。

现有 `LLM_API_KEY / LLM_BASE_URL / LLM_MODEL / LLM_MAX_TOKENS` 与高德变量继续使用，无需额外智能体密钥，不改数据库。公开演示继续使用 `LLM_PUBLIC_DEMO / LLM_DAILY_LIMIT / LLM_CLIENT_DAILY_LIMIT`。额度为调用次数限制，非精确金额上限；未开启公开演示时模型需登录。Cookie、账号记录和密钥不发给模型。

## 模型适配与维护文件

- `travel-agent.mjs`：输入规范、工具协议、有界执行循环、最终结果检查与规则降级。
- `server.mjs`：讯飞适配、身份和配额、高德工具实现、`/api/agent` 路由。
- `decision.js`：需求确认、空候选请求、推荐理由与工具执行记录。
- `showcase.js`：主重排入口；`journey.js`：确认载入与账号保存。
- `scripts/assemble.py`：把智能体源文件打包进 Worker；`scripts/offline.mjs` 保留诚实的离线规则模式。
- `scripts/test-agent.mjs`：25 项真实执行逻辑检查，外部模型和地图响应模拟。

当前使用模型返回 JSON 行动对象，再由应用执行工具。没有配置讯飞 Agent 平台助手 ID，也未把托管平台能力作为已有实现。讯飞 [MaaS 官方 HTTP 文档](https://www.xfyun.cn/doc/spark/%E6%8E%A8%E7%90%86%E6%9C%8D%E5%8A%A1-http.html)对原生 `tools` 有模型范围限制；现有 Spark X2.5 请求参数继续沿用已验证适配，不添加未经该模型确认支持的原生工具参数。

## 验证及下一步

运行 `npm run build && npm run validate && npm test`，总计 13 组检查。`npm run test:agent` 可单独验证智能体；不需要真实密钥。测试覆盖模型自主选点、工具观察、最终检查一致性、错误/重复/排除/闭合地点、固定日期、真实调用路径的模拟交通、未知值、额度、越界工具、轮数上限、取消与草稿不自动写入。

2026-10-12 电脑 1280px / 手机 390px 验证使用隔离的模拟模型；不作为真实模型效果研究。此轮未调用真实模型。更换模型时应先用这些夹具验证协议，再进行受控的实际服务验收，不用固定测试响应冒充生产智能体输出。

后续可增加官方开放/预约信息、天气和价格工具，以及保留明确反馈的多轮修改。必须先增加可验证的数据源、白名单参数和异常测试再对外宣称功能；目前没有实时票价、天气、自动订票、平台托管 Agent 或正式用户效果研究。
