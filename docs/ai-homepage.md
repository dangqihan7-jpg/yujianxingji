# 首页显性 AI 入口

首页 gallery 视图最顶部新增“一句话，让 AI 为你规划河南周末游”区域，原有实景轮播、精选去处、十八城、规划条件、灵感路线及地图的位置关系和功能保留。桌面五张能力卡横向展示，小屏使用紧凑排版；不引入字体、框架或新依赖。

## 交互边界

输入文字后点击“让 AI 规划”，复用现有 openBrief → 需求识别 → 条件确认 → buildCandidate / POST SSE 五阶段流程。仍须确认条件后生成，并确认候选后才替换草稿，不额外自动应用、不另建后端接口。

展示 5 个智能体，名称与顺序为：需求理解 → 地点推荐 → 日程编排 → 交通核算 → 冲突校验。能力介绍是流程说明，不是当前已经完成的进度；交通未核算时保持待确认。服务是否可用及访客/登录状态沿用配置说明，执行来源仍以接口的 ai / rules / confirmed 为准，不能把规则回退当作模型成功。

输入框的呼吸描边只表示可输入，不表示模型正在运行；实际提交时显示真实的请求等待状态。三个示例仅轮换 placeholder，不改用户文字，不替用户发送；聚焦、输入内容、后台、切换视图、打开弹窗与减少动态效果设置均应停止轮换。返回首页或重新渲染时保留尚未提交的需求。

## 文件与验证

- ai-hero.js：首屏内容、示例轮换及已有规划入口桥接。
- ai-hero.css：局部样式与小屏/减少动态效果。
- showcase.js：在现有 gallery 顶部插入及生命周期接入。
- scripts/assemble.py：将入口代码和样式组装入部署文件。
- scripts/test-ai-hero.mjs：首屏渲染、提交桥接、输入保护及轮换回归。
- worker/index.js：构建生成的部署产物，不手工修改。

运行 npm run build、npm run validate 和全量 npm test 后提交。浏览器以375px及桌面验证第一屏、实际本地规则 SSE 与候选确认；模型与地图在隔离测试中不发起真实请求。上线前备份代码和 SQLite，保留账号、分享、私密配置和.local链接。截图、报告及测试/部署日志置于工作区对应证据目录，不提交密钥、数据库、构建目录和无关生成报告。
